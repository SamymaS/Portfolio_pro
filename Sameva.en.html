Sameva: habits become RPG quests

A Flutter mobile app that turns everyday habits into RPG quests. The user photographs their proof, a vision model scores it, and the reward lands as XP, gold and items. Designed, built and shipped solo, from architecture to delivery pipeline, as the project behind the RNCP 39583 certification.

01

The concept

Habits as quests

Users create their own quests (tidying up, cooking, studying, exercising) grouped into areas of life. Completing them earns experience, gold and items, with level progression and streak tracking.

Proof, not a checkbox

The weakness of habit apps is self-declared validation: ticking a box proves nothing. Sameva asks for a photo or a short video, analysed by a vision model that returns a score out of 100. Above 70, the reward is paid in full.

Never stuck

A non-negotiable product principle: if the analysis fails or refuses, the user validates manually for a reduced reward. No network outage and no false negative can ever trap someone in failure. That choice is enforced in code by a systematic fallback service.

A reward that means something

The product thesis fits in one sentence: reaching a real goal deserves a real reward. Hence the meta-game layer, with a companion collection, summons, an item inventory and a leaderboard, giving people a reason to come back tomorrow.

Layered architecture

MVVM across four layers (data, domain, presentation, UI), with state handled through Provider and ChangeNotifier. Roughly a hundred files organised by responsibility, which makes every business rule testable independently of the interface.

Flutter 3DartMVVMProvider

Offline-first

Data is written locally first through Hive, then synchronised with the server. The app stays usable without a network: you can create a quest, validate it and watch your progress, and everything syncs back once the connection returns.

HiveSync

Backend and security

Supabase provides PostgreSQL, authentication and storage, with row-level security policies so every user only ever sees their own data. Five Edge Functions written in Deno and TypeScript carry the logic that must not live on the client.

SupabasePostgreSQLRLSDeno

Authentication journey

Entry requires no sign-up thanks to an anonymous session: you start playing straight away. Users can then create an account by email or through Google, and their progress carries over via identity linking rather than a brand new account.

Anonymous sessionGoogle Sign-InIdentity linking

Monetisation

A freemium model backed by Stripe, with a monthly subscription. Premium status is resolved server-side and never on the device, so no local tampering can unlock paid features.

StripeWebhooksServer-side state

Continuous integration and delivery

Three GitHub Actions pipelines: static analysis and the full 505-test suite on every push, backend deployment, and signed APK builds on version tags. The shipped package is reproducible and signed with a stable keystore.

Fallback, designed in from the start

A simulated validation service is interchangeable with the real one behind the same interface. It lets the whole app run without any API key, which serves both the automated test suite and offline demonstrations.

The same mechanism enforces the “never stuck” principle: if the model is unavailable, the experience degrades but never stops.

What a photo cannot prove

Visual proof covers quests whose outcome is observable: a tidy room, a home-cooked meal, a watered plant. It does not cover duration-based quests, because no still image demonstrates thirty minutes of running.

Those quests call for other proof modes: a built-in timer, a GPS track or a link to a health app. All three are identified and specified, but deliberately out of scope for this first version.
