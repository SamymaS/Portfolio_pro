The project

The brief asked us to demonstrate ten cloud-native concepts on a real application, with a public URL, infrastructure as code and continuous deployment. We picked ticketing because it packs the real problems of a distributed system: two people wanting the same seat, a payment that stops answering, a ticket that must be generated once and only once.

Architecture

Everything runs in an AKS cluster. Traefik takes the traffic and routes it to the front end or the API; the API is stateless, so it can run as many copies as needed.

01

The user picks seats: the API places a short Redis lock on each one.

02

At checkout, the API calls the payment gateway through a circuit breaker, with a timeout and a fallback.

03

Payment accepted: the API publishes a reservation.paid event to the BullMQ queue.

04

The worker builds the QR code and the PDF, stores them in object storage, then acknowledges.

05

The API serves the PDF and the QR check page, never exposing the storage.

03

The patterns, and where they live

Every concept can be checked in the code. Here are the main ones.

No double booking

Atomic SET NX EX lock on every seat: the first request wins, the second gets a 409, and the lock expires on its own if the user walks away.

api/src/holds.js

A slow payment cannot take the site down

opossum circuit breaker with timeout and fallback: after too many failures, the API answers at once instead of piling up requests.

api/src/payment.js

No message is ever lost

BullMQ queue with five attempts, exponential backoff and a kept failure queue. The worker only acknowledges once the work is done.

api/src/queue.js · worker/src/index.js

One ticket, exactly once

Idempotent worker: early guard, ON CONFLICT DO NOTHING and a booking-seat unique constraint in the database.

worker/src/handlers/reservationPaid.js

A database that survives restarts

PostgreSQL as a StatefulSet with a persistent volume, a headless service and readiness probes.

infra/k8s-aks/ticketflow.yaml

Ready for production

/healthz and /readyz routes, structured pino logs, clean shutdown on SIGTERM, Kubernetes probes everywhere.

api/src/health.js · server.js

04

Deliberate choices

Three decisions we defended in front of the jury rather than just accepted.

01AKS rather than Azure Container Apps

Container Apps hides Kubernetes. A real cluster let us show StatefulSets, Ingress, probes and high availability. The trade-off: a cost to watch, and a minikube fallback ready for the demo.

02PostgreSQL inside the cluster

Instead of a managed database: the StatefulSet and persistent volume pattern becomes concrete, and the infrastructure stays easy to reproduce.

03Tickets served by the API

Object storage stays private. PDFs go through an authenticated route instead of an exposed storage URL: a better security posture.

05

Delivery

Terraform provisions the resource group, image registry, AKS cluster, storage and secret vault. On every push to main, GitHub Actions builds and publishes the four images, then updates the cluster.
